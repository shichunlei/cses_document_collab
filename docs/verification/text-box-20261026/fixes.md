## 修复结果

### R1：框内未知对象不再阻断框外保存

原生文本框子块校验允许正式投影的不透明占位；写入仍经过既有的占位身份、原父级及全部字段不变检查。新增或伪造unsupported节点、修改/移动/删除原占位、转换其类型，以及删除包含它的父框均在写入前拒绝，不放开占位内容的编辑权限。

Rust回归把未知对象直接插入已发布Schema工厂夹具的Y.Text，再修改框外正文；比较原始块JSON及完整Y.Text Delta（含对象及格式），确认不重写未知内容。6种非法快照全部原子拒绝，共享状态编码不变。真实FRB/Yrs/SQLite回归验证框外保存、撤销、重做、关闭重开及占位父子身份；根级未知段落对照保留。当前视图仍按原规则保护含占位内容的文本框，本轮不扩大框内未知对象的编辑能力。

### R2：添加入口和实际命令统一检查父容器

T类型菜单、添加面板的共用插入/转换、常用动作和资源插入共用文本框子块限制。添加面板按捕获书签的实际父级隐藏代码、图片及嵌套文本框等不合法选择；命令提交时再次检查，避免仅隐藏入口仍可绕过。行内动作不被当成块插入禁用，非文本框位置保持原有能力。

覆盖空/非空正文拒绝代码与图片且不产生历史、段落/标题/引用及三类列表可正常插入并独立撤销、框外仍可插入代码。真实添加面板验证不显示非法项，并通过同一面板添加合法引用，保护修复后正文编辑与焦点恢复流程。

### R3：预览和编辑的内部滚动状态隔离

纯预览使用独立PageStorageKey，固定框从顶部裁切；编辑模式继续使用原稳定Key保存自己的位置。验证编辑滚动到250逻辑像素→预览为0→返回编辑恢复250→再次预览仍为0。没有新增控制器、监听或异步资源。
