## 结论与依据

在本轮静态检查和可控异步验证范围内，保存失败提示问题已解决，未发现该修复引入新的并发问题。

- `_save` 用本轮局部变量记录写入错误，冲突补读明确携带该错误；读取开始、读取成功和读取失败均不会清除或替换本轮写入失败提示。写入失败仍返回 false，头部现有 SnackBar 能消费该提示。
- 成功写入后的补读不带旧错误，补读失败仍显示加载错误；后续独立刷新或新一轮保存可以清除旧错误，没有把上轮失败状态绑定到下一轮。
- 补读仍在整轮保存锁内，重复保存被拒绝，期间 refresh 不发送额外读取或清空提示。远端新补丁仍按读取周期重放，保留比 HTTP 更新的字段。
- 错误变量只属于当前写入任务，不增加共享 Future、监听或资源。关闭期间仍等待在途读取/保存，关闭后的成功或失败结果均不再回写；完成通知同步启动下一轮写入时，旧任务不会清除新任务的等待引用。
