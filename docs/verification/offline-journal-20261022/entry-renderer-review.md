# 今日导向业务行渲染审查与真实 Widget 验证

日期：2026-10-22。审查宿主 `guidance_entries.dart` 与实际 `JournalSurface` 集成，重点为原生节点定位、原子提及、首行符号、横格及编辑/预览一致性。本记录不替代设备输入法或企业业务服务验收。

## 发现与修正依据

1. **业务行回车边界**：通用段落回车默认继承同类段落属性，若宿主直接委托，会把 `guidance_entry`、业务 ID 和本地完成状态带到下一段。已反馈由宿主 `journal_editing.dart` 优先处理业务行，不修改包的通用回车行为。此项的具体编辑和撤销验收以本轮控制器/输入测试为准。
2. **提及字号重复缩放**：真实页面在 2 倍字号下测得首行高 128 逻辑像素，而同源正文应为 64。Flutter 的 `WidgetSpan.extractFromInlineSpan` 已通过 `_AutoScaleInlineWidget` 应用外层 `RichText` 的字号倍率，内部 `Text` 再设置同倍率造成重复放大。宿主已将内部 `Text` 设为 `TextScaler.noScaling`，由外层统一控制缩放。[初始失败证据](entry-layout-initial-failures.log)。
3. **长名称把原子占位符撑成多行**：合法的 140 字引用名称在 1 倍字号下把首行撑到 224 逻辑像素，固定首行圆环/标签与行线因此不再匹配。宿主已限制提及内部文字单行并省略超长显示；模型仍保留完整名称和单个原子对象，不截断保存数据。[初始失败证据](entry-long-name-initial-failure.log)。

审查者没有直接修改上述生产文件；修正由本轮主实现应用，随后运行同一真实页面回归。

## 节点、选区和存储结论

- 业务外壳不占用 `node.key`，内部唯一的 `ParagraphBlockComponentWidget` 持有该 key，保留原生 `Selectable`。测试实际读取 `node.key.currentState` 和 `node.selectable`，并在编辑/预览各轮核对，未出现重复 GlobalKey 或节点定位丢失。
- 提及使用带受控引用属性的 U+FFFC，占一个模型字符；真实 `RenderParagraph` 的提及左右命中位置分别映射到偏移 0 和 1。普通文字仍由原生段落输入和布局处理，圆环/标签不计入文本长度。
- 1 倍字号单行 32、2 倍字号单行 64 逻辑像素；自动换行、长名称下仍按同一正文行距绘制横格，圆环、都来帮和领航员标签均对齐首行。预览沿用同源排版，布局快照逐项一致。
- 本地待办勾选通过 `EditorState.apply(transaction)` 更新属性，真实页面回归验证自动保存快照含 `guidance_done: true`，未在 Widget 内直接写存储。
- 新增整合用例从页面“@用户”按钮打开组织多选，确认人员和部门后插入原有句子的指定光标位置，保持原文、原子身份和部门整体引用；随后核对本地保存，取消另一次都来帮选择不生成空业务行，预览仍显示相同提及。
