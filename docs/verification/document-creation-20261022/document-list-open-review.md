## 审查重点

- 首页正式模式只初始化账号服务、恢复创建记录并启动主 WebSocket；默认 ID、指定初始文档参数及首页直接编辑入口已移除。completed 记录不触发文档打开，无文档时重连和前台恢复仍有效。
- 列表回调在打开前及异步完成后检查当前路由和组件有效性，借用固定的已初始化控制器推入编辑页；列表退出或被其他路由覆盖时不会迟到导航。
- 普通打开先通过 Common HTTP 核验访问及返回 ID，再经过同一协调器串行关闭和打开文档。拒绝访问保留原控制器，不写创建记录、不准备空白正文。重复打开与创建之间不会误共享另一文档 ID。
- 同一已初始化文档按现有离线策略复用控制器与历史；仍核对账号并经过操作锁。权限异步请求、文档切换、连接恢复及账号关闭的等待顺序未发现跨文档回写问题。
- 新建成功刷新列表，并从仍有效的列表路由进入编辑页；返回后恢复交互。被覆盖时保留已创建 ID，后续普通打开成功不会继续引用旧的新建结果。
- 对照当前 Java 的访问授权及列表查询：`DocumentQueryHandler.read` 使用 `Action.access`；当前 Java `DocumentType` 仅声明 text，列表不按文档子类型筛选的现状没有新增可确认的其他文档类型误开问题。客户端更广的类型分流不能替代当前 Java 契约，真实部署行为仍需联调确认。
